# ZIV.AI 产品规格（SPEC）

- 文档状态：草案 v0.1（待评审）
- 适用范围：Windows 桌面端（必须兼容 Win10，不依赖 Win11 专属 API）
- 目标：定义 ZIV.AI 的功能范围与行为契约，作为实现 / 验收的唯一基准
- 上游：本项目从 ZIV（`D:\devlop\ZIV`）派生，**复用** `ZIV.Core` 与 `ZIV.Imaging` 的类型与算法，
  但**不进入 `ZIV.sln`、不依赖 `ZIV.App`**；接口与实现细节见 [`ARCHITECTURE.md`](ARCHITECTURE.md)
- 继承约束：ZIV 的铁律 **Z1–Z16 继续适用**（见 §6），本文件在其后**续接 Z17–Z28**

## 1. 定位

ZIV.AI 是一个**独立的新项目**，同时具备两种形态：

1. **AI 图像编辑独立应用**：自带解决方案 `ZIV.AI.sln`、自带可执行入口
   `ZivAiEditor.App.exe`，双击即可运行，**不要求 ZIV 存在或运行**（Z28）。
2. **进程外插件**：被 ZIV 主程序**可选**调用，经命令行 / 自定义 URL 协议 / 本地 HTTP /
   命名管道通信（Z27），ZIV 侧不加载任何 AI 托管代码。

核心能力一句话：

> **三图槽位（主图 / 参考图 / 遮罩图）+ 一句自然语言 → 自动规划编辑步骤并执行。**

核心原则：**全本地、不联网、不破坏原图、推理进程隔离、模型空闲卸载。**

- 定位与 ZIV 的关系：ZIV 是**看图软件**（查看 / 相册 / 旋转翻转），ZIV.AI 是**图像编辑软件**；
  两者共享底层库，但**运行时是两个独立进程**，可分别安装、分别更新、分别运行。
- 精细活（专业级图层、笔刷、色彩管理）明确不做，交给 Photoshop（§5）。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 主图 | 被编辑的目标图像（`MainImage`），编辑以它为基础，输出为新文件 |
| 参考图 | 可选输入，为风格 / 内容 / 构图提供参考（`ReferenceImage`） |
| 遮罩图 | 可选输入，二值 PNG（只含 0 / 255），标记可编辑区域（`MaskImage`，见 `MaskSpec`） |
| 提示词 | 用户输入的一句自然语言编辑指令（`Prompt`） |
| 提示词模板 | 预置的指令骨架（如「把主图的 ___ 改成 ___」），用户可套用后修改 |
| 计划 | `EditPlan`，Planner 对一次请求产出的有序步骤集合 |
| 步骤 | `EditStep`，计划中的一个原子编辑动作，绑定一个工具与一组参数 |
| 工具 | `IEditTool` 的实现，执行单一步骤（如抠图 / 重绘 / 扩图 / 风格迁移） |
| 工具注册表 | `IToolRegistry`，按名称 / 能力查找工具，供 Planner 与 Executor 使用 |
| 推理后端 | 本地 Python 服务（Qwen-Image-2.1 + SGLang；Step 1 单主线，LightX2V 为 Step 7 可选加速），经 HTTP 暴露模型能力 |
| Agent | `ZivAiEditor.Agent`，规划（Planner）与执行（Executor）的编排者 |
| Planner | `IPlanner`，把「三图 + 提示词」翻译成 `EditPlan`（可降级，Z22） |
| Executor | `IExecutor`，按 `EditPlan` 顺序调用工具、汇报进度、支持取消与重跑 |
| 任务卡片 | UI 中表示一个任务（`TaskState`）的卡片：显示步骤、进度、结果、重跑按钮 |
| 任务 | `TaskState`，一次用户提交的完整编辑请求及其步骤执行记录 |
| 推理客户端 | `IInferenceClient`，C# 侧访问推理后端的唯一契约（HTTP / 命名管道实现） |
| 进程外插件 | ZIV.AI 以独立进程被 ZIV 调用的形态（Z27），不经进程内插件 ABI |

## 3. 功能规格

### 3.1 三图 + 一 prompt 输入

- **行为**：
  1. 提供三个图像槽位：**主图**（可选：缺省且 `Prompt` 非空时为 **T2I 文生图**）、
     **参考图**（可选）、**遮罩图**（可选）
  2. 提供一句自然语言提示词输入框（`Prompt`）
  3. 用户提交后，Planner 结合三图与提示词产出 `EditPlan`
- **边界**：
  - 主图缺失时，若 `Prompt` 非空则生成 **T2I（文生图）** 任务（`op="t2i"`，
    纯文本条件 + 零 latent）；若 `Prompt` 也为空，禁止提交并给出明确提示
  - 参考图 / 遮罩图缺省时，计划中相应步骤自动降级或省略（由工具能力决定）
  - 图像只以**路径 + 显式传入**的方式交给后端；C# 侧不预填充遮罩（Z19）
- **通过标准**：三图齐全 / 仅主图 / 仅 `Prompt`（T2I）三种情形都能产出可执行计划；
  主图与 `Prompt` 同时缺失被拒绝

> **Step 7 修订**：原 §3.1 要求「主图必填、缺失即拒绝」。T2I 落地后，主图缺失不再一律拒绝：
> 有 `Prompt` 即转 T2I。契约见 `FROZEN.md` Step 7 / `contracts/ipc-protocol.md` §3.4（`op="t2i"`）。

### 3.2 手绘遮罩（画笔 / 橡皮 / 撤销）

- **行为**：
  - 在遮罩画布（`MaskCanvas`，Avalonia 自绘）上以画笔涂抹、橡皮擦除
  - 提供**撤销**（至少多级）与清空
  - 完成后导出为**二值 PNG**（只含 0 / 255）作为遮罩图
- **边界**：
  - 画布坐标与主图像素坐标必须可映射（含缩放 / 平移下的映射）
  - 导出结果不得含半透明 / 中间灰度值（Z19）
  - 撤销栈有上限，超出按最早淘汰（有界，Z12 精神）
- **通过标准**：涂抹 → 撤销 → 再涂抹结果正确；导出 PNG 用像素检查只有 0 与 255

### 3.3 提示词模板

- **行为**：
  - 内置一组常用编辑指令模板（如「去除 ___」「把 ___ 替换为 ___」「扩展画布到 ___」）
  - 用户选择模板后填入提示词框，可继续编辑
- **边界**：
  - 模板只是文本骨架，不绑定特定模型或工具；具体步骤仍由 Planner 决定
  - 模板列表可扩展，但**不引入联网下载**（§4）
- **通过标准**：选择任一模板能正确填充提示词框且不覆盖用户已输入的正文（需确认策略）

### 3.4 任务卡片流

- **行为**：
  - 每次提交生成一张**任务卡片**，卡片展示：任务状态、步骤列表、每步进度、结果缩略图
  - 卡片按提交顺序排列成流；支持查看历史任务
  - 卡片上提供**重跑**操作
- **边界**：
  - 卡片状态与 `TaskState` 持久化记录一致（Z20）
  - 历史卡片只读展示，重跑生成新任务（不覆盖旧记录）
- **通过标准**：连续提交 3 个任务，卡片顺序与状态正确；关闭重开应用后历史仍在

### 3.5 多步执行 + 进度 + 重跑

- **行为**：
  - Executor 按 `EditPlan` 顺序执行步骤，逐步汇报进度（`IProgress<T>`）
  - 支持**取消**正在执行的任务
  - 支持对单个任务 / 单个步骤**重跑**
- **边界**：
  - 步骤失败时任务标记失败并保留已完成步骤的中间结果（Z24）
  - 重跑必须可复现（参数 / 输入路径入 SQLite，Z20）
  - 所有推理请求经**单一队列**串行执行（Z18）
- **通过标准**：多步计划按序执行、进度单调递增；取消后不再有新的推理请求；重跑结果与首次一致

### 3.6 对外接口（CLI / URL 协议 / HTTP）

- **行为**：
  - **CLI**：`ZivAiEditor.App.exe` 接受主图路径与参数（如 `--image <path> --prompt <text>`）
  - **URL 协议**：注册自定义协议（如 `zivai://edit?...`），供 ZIV / 看图软件唤起
  - **本地 HTTP API**：暴露 `/v1/health`、`/v1/inpaint`、`/v1/task/{id}` 等（见 `contracts/openapi.yaml`）
- **边界**：
  - 所有接口**只监听本地回环**，不对外网开放（§4）
  - 单实例：重复唤起应复用已有进程并转发请求（参考 ZIV `SingleInstance` 思路）
  - 接口契约以 `contracts/openapi.yaml` 为准，Step 1 冻结
- **通过标准**：三种入口都能触发同一次编辑任务；契约与 OpenAPI 草案一致

### 3.7 模型空闲卸载

- **行为**：
  - 推理后端在**空闲超时**后释放模型显存；保留最近使用的一个模型（Z21）
  - 超时时长**可配置**
- **边界**：
  - 卸载不得影响任务状态（任务数据在 SQLite，Z20）
  - 下次请求触发重新加载，加载期间 UI 显示加载状态
- **通过标准**：空闲超时后显存占用下降；再次请求能自动重载并成功

### 3.8 不破坏原图

- **行为**：
  - 编辑结果**只写入新文件**，绝不覆盖主图原文件（Z24）
  - 中间结果保留，可回溯到任一步骤
- **边界**：
  - 输出路径默认与主图同目录、追加 `_ai_{timestamp}` 后缀（裁决 5；详见 §3.9），冲突时自动避让
  - 中间结果有清理策略（有界，Z12 精神）
- **通过标准**：编辑前后主图文件字节级一致；输出文件存在且可打开

### 3.9 输出目录与遮罩坐标策略

> **Step 1 裁决落地**（见 `FROZEN.md` 顶部修订说明与 1.4 裁决落地表）。

**输出目录策略（裁决 5）**

- **单图编辑**：默认输出到**主图所在目录**，文件名追加 `_ai_{timestamp}` 后缀
  （如 `photo.png` → `photo_ai_20260921_090000.png`）；同名冲突时自动避让。
- **批量 / 无主图场景**：输出到**程序目录 `output/`**（随程序目录，Z14）。
- 一律**新文件**，绝不覆盖原图（Z24 / §3.8）；中间结果保留，可回溯。
- 调用方可显式指定输出路径；显式指定优先于默认策略。

**遮罩画布坐标策略（裁决 6）**

- **内部约定**：遮罩一律以**主图原始像素坐标**为准（`MaskSpec.Width` / `Height` 即主图原始尺寸）。
- **显示变换只在 UI**：缩放 / 平移 / 适配（fit）只影响画布显示，不得写入遮罩数据。
- **导出映射回原始像素**：从画布导出二值 PNG 时，把显示坐标反算回原始像素，保证
  `MaskSpec` 与主图像素一一对应（Z19）。
- C# 侧**不预填充**遮罩；导出即最终二值数据（只含 0 / 255）。

**端口与 `settings.ini`（裁决 4）**

- 后端端口**动态分配**：Python 后端启动时选择一个空闲端口，写入**程序目录**
  `settings.ini` 的 `backend.port` 键（数据随程序目录，Z14）。
- C# 侧启动时读取 `settings.ini` 的 `backend.port`，据此访问 `http://127.0.0.1:{port}`。
- 不使用固定端口，避免与其他应用冲突；重复唤起由单实例机制复用同一进程与端口。

## 4. 隐私

- **全本地**：所有推理在本机完成，**不联网**（模型、Python 后端、依赖全部本地）
- **无遥测**：不采集、不上传任何使用数据
- **不外传图片**：不读取、不上传用户图片内容到任何远端
- **网络面收敛**：本地 HTTP API 只绑定 `127.0.0.1` / `localhost`，禁止绑定 `0.0.0.0`

## 5. 非目标（本期）

- **专业级图像编辑**：图层、蒙版混合模式、专业笔刷引擎、色彩管理（ICC 级），
  精细活交给 Photoshop；ZIV.AI 只做「AI 驱动的编辑步骤」
- **云服务**：不做云端推理、账号、同步、协作
- **跨平台**：只做 Windows（Win10 优先）
- **模型训练 / 微调**：只做推理调用，不训练
- **通用插件平台**：不对第三方开放工具插件 ABI（内部工具走 `IToolRegistry`）
- **替代 ZIV 的查看能力**：ZIV.AI 不做相册 / 批量重命名 / 批量缩放等看图软件功能

### 6.2 ZIV.AI 续接铁律 Z17–Z28

**Z17 · AI 推理进程隔离** — C# 不直接加载 Python 运行时，不 P/Invoke Python C API，
只经本地 HTTP 或命名管道。C# 进程与 Python 进程边界清晰：C# 侧只依赖 `IInferenceClient`
契约，后端可独立替换 / 升级（Z23）。
原因：Python 运行时与 .NET 混载会带来版本冲突、崩溃扩散、AOT 不兼容。

**Z18 · GPU 资源串行** — 所有推理请求进**单一队列**，RTX 4080 16GB 上**不并发**；
交互任务优先于批处理任务；显存不足（OOM）时按预设策略**降级重试**（降分辨率 / 降步数 /
换轻量模型），不得直接崩溃或静默失败。
原因：单卡显存有限，并发会导致 OOM；串行 + 优先级是稳定性的前提。

**Z19 · 遮罩二值且不预填充** — 遮罩 PNG **只含 0 / 255**；原图与遮罩**分开传**；
禁止 C# 侧对遮罩做预填充（如自动膨胀、羽化、补边）。任何遮罩处理由后端在收到
原始二值遮罩后进行，且处理方式必须可配置 / 可追溯。
原因：C# 侧预填充会污染用户意图，且与后端算法重复、不可复现。

**Z20 · 任务状态持久化** — 任务 / 步骤 / 参数 / 输入输出路径 / 耗时写入 SQLite；
支持**恢复**（重启后任务历史与状态不丢）与**取消**。任务状态是唯一事实来源。
原因：AI 推理耗时长，用户需要可追溯、可重跑，崩溃后不能丢。

**Z21 · 模型空闲卸载** — 空闲超时释放显存；**保留最近使用的一个模型**；超时时长**可配置**。
原因：单卡显存需在多个模型 / 其他应用之间共享，常驻会挤占资源。

**Z22 · Planner 可降级** — LLM 解析失败时**回退默认计划**（如单步「按提示词直接重绘」）；
Planner 实现**可替换**（`IPlanner` 多实现，接口不变）。
原因：LLM 输出不稳定，必须有确定性兜底，否则整个应用不可用。

**Z23 · AI 模块独立更新** — AI 模块（C# 侧）可单独更新；Python 后端可单独升级，
两者版本解耦，通过 `contracts/openapi.yaml`（**Schema 参考**）或
`contracts/ipc-protocol.md`（**IPC 传输契约**）通信。禁止要求二者必须同时升级。
原因：Python 生态迭代快，C# 侧应保持稳定；契约版本化是解耦的前提。
（Step 2 补充：后端改为 ComfyUI in-process，跨进程走 IPC 契约，见 `FROZEN.md` Step 2。）

**Z24 · 不破坏原图** — 输出到**新文件**；中间结果保留；结果可**回溯**。
禁止对主图原文件做任何写入 / 改名 / 删除。
原因：编辑软件的第一安全底线；AI 结果不可预测，必须可撤销、可对比。

**Z25 · AI 模块独立解决方案** — 独立 `ZIV.AI.sln`；**不进 `ZIV.sln`**；不共享构建产物
（`bin` / `obj` / publish 各自独立）。
原因：两个应用发布节奏不同，混在一起会导致构建耦合与版本冲突。

**Z26 · 共享库不复制** — `ZIV.Core` / `ZIV.Imaging` 在仓库中**只有一份**；
AI 模块通过**项目引用或 NuGet 引用**使用，禁止 fork / 拷贝源码副本。
原因：复制会产生分叉，ZIV 侧的修复无法同步到 ZIV.AI。

**Z27 · 进程隔离不破** — AI Editor 与 ZIV 是**独立进程**；ZIV 只经命令行 / URL 协议 /
命名管道调用 ZIV.AI。ZIV 不得加载 ZIV.AI 的托管程序集，ZIV.AI 不得反向依赖 `ZIV.App`。
原因：插件崩溃不得拖垮主程序；主程序升级不得迫使 AI 模块重编译。

**Z28 · 独立运行不依赖 ZIV** — `ZivAiEditor.App.exe` 启动**不要求 ZIV 存在或运行**；
ZIV 只是可选的调用方，不是运行前提。
原因：ZIV.AI 是独立产品，不能把 ZIV 的安装状态变成硬依赖。

**Z29 · 测试按影响面执行** — 每次代码改动后，只跑**受影响的测试类**；全量测试仅在
**Step 收尾**或**明确需要**时执行。测试选择依据：改动文件的引用关系 + 测试类的覆盖范围；
全量测试的触发条件：Step 收尾、发布前验证、跨模块重构。**禁止**无差别的「每次改动都跑全量」。
**核心动机：保护硬件资产** —— 端到端 GPU 测试每次加载 16GB 模型、跑满显存峰值
（1024 下 16004/16376 MiB）；GPU 长期高负载缩短寿命，RTX 4080 16GB 市价约 1 万元，
硬件损耗成本远高于多跑一次测试的收益。**原则：出错了再修** —— 测试是为发现已发生的
问题，而非预防所有可能性。冻结于 `FROZEN.md` Step 5。

**Z30 · GPU 任务先确认空闲** — 任何会占用 GPU 的任务（推理、端到端测试、基准脚本、
模型加载）在启动前**必须先确认 GPU 空闲**（无其他计算进程、显存占用接近基线）；若 GPU
**不空闲**（存在其他占用或显存余量不足），**必须与用户确认后才能继续**，不得自行启动。
**核心动机：保护硬件资产** —— 16GB 单卡上并发或超出显存预算的任务会 OOM，甚至拖垮整机
（实测教训：2026-09-22 未确认 GPU 空闲、且未按 `DOC/OPTIMIZATION.md` §6.1 的显存数据预留
余量，同进程连跑两次 1536×960 采样，导致系统崩溃）。冻结于 `FROZEN.md` Step 6。
